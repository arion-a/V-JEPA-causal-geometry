# Protocol A — Causal Geometry in V-JEPA 2.1 (Pilot)

**Status:** preregistration-ready design; no experiment has been run.  
**Primary model:** frozen V-JEPA 2.1 Large encoder, exact checkpoint hash recorded before execution.  
**Target:** 200 distinct rendered clips; **budget ceiling:** $25 initial GPU rental; **timeline:** 1–3 working days after checkpoint and simulator are working. Estimates are not benchmarks.

## 1. Question and competing hypotheses

Does a pretrained video encoder represent physical generating mechanisms in a context-transferable manner, rather than only the trajectories and appearances they produce?

- **H1, local sensitivity:** changes in gravity, restitution, and friction yield reliable, distinguishable changes in latent representation where each parameter is physically observable.
- **H2, cross-context transfer:** gravity intervention directions align more across different scenarios than matched random intervention directions and visual nuisance changes.
- **H3, nuisance separation:** physical-intervention and visual-nuisance tangent spaces become more separable at some layers.
- **H4, local composition:** latent changes for simultaneous physical interventions are predicted by the sum of individual local changes, better than suitable baselines.
- **Null/alternative:** apparent structure is attributable to trajectory differences, image statistics, object identity, or pooling choice rather than encoding causal mechanisms.

**Interpretive limit:** rank, alignment and compositionality alone do not establish causal identification. Similar images generated by different mechanisms may be observationally indistinguishable to a video-only model.

## 2. Experimental units and rendering rules

A **base world** is a scenario with fixed initial conditions, geometry, camera, lighting, random seed and simulation clock. An **intervention family** consists of baseline and counterfactual clips differing in exactly one assigned parameter (or two for composition). One clip is one rendered video; layer activations are repeated measures, **not** independent samples.

- Simulator: deterministic MuJoCo or PyBullet with explicit logged engine version, timestep, integration settings, contact parameters, RNG seed and renderer.
- Fixed video duration, FPS, frame count and resolution compatible with the selected checkpoint; log any temporal subsampling and resizing.
- Exclude parameter tests where no observable physical event occurs (e.g., restitution without collision; friction without contact).
- Prefer fixed camera and background within matched counterfactual pairs; vary them deliberately in nuisance controls.
- Use symmetric physical interventions, checking that both perturbed settings remain valid and actually affect motion.
- Record object trajectories and collision/contact events from the simulator as ground truth.

The ten nuisance-control worlds should be balanced across the three physical scenarios. The composition family is distinct from the earlier worlds for a clean exploratory check; choose the second parameter as restitution in bounce and friction in incline. Lighting can be added later as a separate nuisance condition. Note that a single-sided composition test cannot establish curvature robustly.

**Train/test separation:** no model is trained, but if tuning perturbation magnitudes or selecting layers, use 5 base worlds per primary scenario for development and 5 for held-out assessment; report exploratory versus held-out findings separately. Predeclare primary layer summary to avoid cherry-picking.

## 4. Representation extraction

1. Download weights and source from the official release; pin commit, checkpoint SHA256, model config, and license.
2. Load model in inference/eval mode, freeze parameters, disable stochastic transforms.
3. Verify exact tensor shape and output token ordering at each encoder block with hooks.
4. Capture all layer representations for each clip; use both pooled tokens and a selected spatial/temporal token analysis.
5. Stream features to disk to avoid holding every activation in GPU RAM; verify identical outputs on repeat inference.
6. Preserve consistent normalization: compare raw and L2-normalized features as separate analyses; do not conflate their geometries.

## 5. Mathematical analysis

For physical parameters θ=(g,e,μ), context c, and layer l:

`z_l(θ,c) = E_l(render(θ,c))`

Central difference for a valid mechanism j:

`v_{j,l}(c) = [z_l(θ+δ_j e_j,c) − z_l(θ−δ_j e_j,c)]/(2δ_j)`

`J_l(c) = [v_g, v_e, v_μ]` restricted to parameters observable in that context. Do **not** report rank 3 for free fall or any scenario with fewer than three identifiable mechanisms.

- **Numerical reliability:** compare forward vs central differences where possible; perturbation sizes must exceed numerical/rendering noise but remain locally small. Repeat a subset at δ/2 and 2δ in an extension.
- **Identifiability:** singular values, effective rank, column cosine similarities, condition number and bootstrap uncertainty.
- **Cross-context:** compare gravity-direction cosine similarity and principal angles between scenario-specific intervention subspaces; compare against shuffled pairing and matched trajectory baselines.
- **Mechanism–nuisance:** principal angles and projection overlap between physical and appearance/camera tangent spaces, when the controls are comparable.
- **Induced metric:** `G_l(c)=J_l(c)^T J_l(c)`; report parameter units and standardized perturbations before comparing matrix entries.
- **Composition:** `E_comp = ||Δz_both − (Δz_g + Δz_second)||² / max(||Δz_both||², ε)`; compare against a no-change and trajectory-based baseline. Report absolute residual too.
- **Layer trend:** use matched context-level statistics across layers, not one independent test per activation.

## 6. Required controls and inference safeguards

- **Positive control:** known kinematic variables decoded from simulator trajectories should respond correctly to interventions.
- **Negative controls:** unchanged duplicate renders, shuffled intervention labels, color/camera nuisance, and unrelated interventions.
- **Critical cause-vs-effect control (pilot extension if budget permits):** engineer different causes producing closely matched visible trajectories. Without this, mechanism-vs-kinematics claims remain tentative.
- Compare latent results to pixel difference, optical flow/trajectory features and simple handcrafted state vectors.
- Use base world as bootstrap/resampling unit; report confidence intervals and effect sizes. Multiple layers and metrics are exploratory unless a primary test is preregistered.
- Set minimum valid-render and numerical stability criteria before interpreting results.

## 7. Operational workflow

**Gate 0 — Environment (2–6 hours):** model loads, one video renders, features extracted, SHA hashes recorded. Stop if checkpoint or hook mapping is uncertain.

**Gate 1 — 20-clip smoke test (1–3 hours):** validate fixed seeds, physical trajectories, deterministic embeddings, finite differences and disk outputs. Stop if interventions do not alter the relevant physical event.

**Gate 2 — 200-clip experiment (2–8 hours, hardware-dependent):** render all clips, batch inference, store features and metadata. Measure throughput after first 20 clips before approving remaining rental.

**Gate 3 — Analysis (4–10 hours):** compute metrics, uncertainty, baselines, layer plots, and failure-case examples.

**Gate 4 — Decision:** proceed to expanded experiment only if extraction is reliable and at least one predeclared physical-vs-control contrast is reproducible across held-out contexts; a null result is reportable.

## 8. Compute, storage and cost

- **Preferred:** single 24–48 GB GPU for 300M checkpoint, reduced batch if needed; 80 GB A100 is a convenience, not a requirement. Actual VRAM depends on clip length/resolution and attention implementation.
- **GPU rental planning:** 3–10 billed hours including setup/reruns; target $10–25 total at low-cost on-demand rates. Not a guaranteed quote.
- **Storage:** video clips, checkpoint, feature arrays and analysis artifacts; provision 20–100 GB initially and measure actual usage. All-layer token storage can exceed video size.
- **Time:** 1–3 working days for a working codebase; more if simulator/rendering or checkpoint API requires debugging.

## 10. Pilot success criteria

- All 200 planned clips valid or failures documented; deterministic repeats within numerical tolerance.
- Every estimated mechanism direction corresponds to an observable intervention in that context.
- Layer-wise effect sizes, uncertainty intervals and baseline comparisons delivered.
- Held-out contrasts and negative controls reported regardless of direction of result.
- Go/no-go recommendation grounded in empirical throughput and evidence, not only visualizations.
